# Maydonlar — серверная версия 0.2.28

Исходный код и документация: [GitHub](https://github.com/malikvalikhodjaev/adspace). Исходные DOCX с требованиями хранятся локально у владельца проекта и не входят в публичный репозиторий.

Основной адрес: `https://maydonlar.fom-analytics.uz/`. Прежние `https://maydon.fom-analytics.uz/` и `https://adspace.fom-analytics.uz/` остаются рабочими алиасами, в том числе для уже выданных ссылок LED-плееров. Аккаунты и данные общие; на новом поддомене потребуется войти повторно, поскольку сессионная cookie привязана к хосту. Внутренние имена каталога, службы, базы и cookie не менялись. Перенаправление обычных страниц с обоих прежних хостов готово, но по умолчанию выключено (`MAYDON_REDIRECT=0`) ради совместимости во время перехода.

## Основные ссылки и сценарий

| Для кого | Адрес | Что проверять |
| --- | --- | --- |
| Заказчик | [Главная](https://maydonlar.fom-analytics.uz/) · [Каталог](https://maydonlar.fom-analytics.uz/?view=catalog) · [Мои размещения](https://maydonlar.fom-analytics.uz/?view=orders) | Экран → календарь свободного времени → материал → запрос → статус |
| Владелец экрана | [Партнёрский ленд](https://maydonlar.fom-analytics.uz/partners) · [Мои экраны](https://maydonlar.fom-analytics.uz/?view=operator) | Черновик/публикация экрана → занятость → входящий запрос → согласие владельца |
| Администратор платформы | [Техническая админка](https://maydonlar.fom-analytics.uz/admin) | Общие показатели экранов и календарей, аккаунты, комиссия; вход только с ролью `admin` |
| Показ | [Пример сетки](https://maydonlar.fom-analytics.uz/devshow) | Синтетическая демонстрация; ссылка на живую сетку и закрытый браузерный плеер конкретного экрана выдаётся владельцу в кабинете |

Календарь заказчика и владельца общий по данным, но показан с разных сторон. Новый экран можно опубликовать без согласования платформой. Отправленное размещение подтверждает **владелец каждого выбранного экрана**; отдельного одобрения платформой нет. После последнего согласия материал попадает в расписание браузерного плеера на согласованные даты и часы по времени Ташкента. Просмотр `/devshow` не считается показом. Физический LED/CMS, реальные платежи и юридическая электронная подпись пока не подключены.

Актуальное архитектурное решение — [ADR-002](docs/architecture/ADR-002-Maydonlar-server-MVP.md); серверные детали — [SERVER-PILOT.md](docs/SERVER-PILOT.md). [ADR-001](docs/architecture/ADR-001.md) и прежние описания ниже относятся к историческому прототипу и ранним версиям, а не к текущему пути размещения.

## Исторические заметки (не описание текущего процесса)

Версия 0.2.15: админка находится по `/admin`, без ссылки в основной навигации. Если администратор ещё не вошёл, с этой страницы открывается существующий email-вход. Доступ по роли по-прежнему проверяется сервером.

Версия 0.2.14: номер телефона стал основным входом для просмотра сценария. Код показывается на странице, SMS не отправляется и номер не считается подтверждённым; существующий профиль открывается только при наличии привязки к тому же браузеру. Email и пароль перемещены в свёрнутый запасной вход.

Версия 0.2.13: владельцы сохраняют LED-экран черновиком или публикуют его сами без согласования карточки; форма показывает только основные поля, остальное свёрнуто. Карточку можно открыть в режиме посетителя, включая закрытый предпросмотр черновика. Модерация материалов для размещений остаётся отдельным процессом. Узбекская фраза на главной уточнена до «Shaharning bir kichik qismini o‘zingizniki qiling».

Версия 0.2.12: узбекский заголовок главной стал «SHAHAR SIZNI ko‘rsin.»; текст под ним использует мысль «Shaharning kichik bir qismini o‘zingizniki qiling» и сохраняет прямое объяснение размещения фото, поздравления или рекламы.

Версия 0.2.11: на главной три шага размещения разделены заметными горизонтальными и вертикальными линиями по референсу; на узком экране вертикальные границы становятся горизонтальными. Цветовые акценты Maydon сохранены.

Версия 0.2.10: пять больших карточек сценариев убраны с главной. «Разместить» открывает короткий необязательный выбор, а «Посмотреть экраны» ведёт сразу в каталог. Выбранный сценарий остаётся в URL и подсказывает подготовку материала при оформлении, не фильтруя экраны; старые ссылки `/#ideas` продолжают открывать выбор.

Версия 0.2.9: узбекская главная использует прямой заголовок «KATTA EKRAN. siz uchun.», фразу с «oson joylashtiring» и короткие кнопки «Joylashtirish» / «Ekranlar». На первом экране мелкий интерфейсный текст переведён на системный шрифт с увеличенным размером кнопок; фирменный жирный шрифт заголовков и красная палитра сохранены.

В версии 0.2.8 основным адресом был `https://maydon.fom-analytics.uz/`, а `https://adspace.fom-analytics.uz/` оставался алиасом. Тогда подготовили переключаемое перенаправление обычных страниц; ссылки `/player/…` и `/screen/…` всегда сохранялись на прежнем домене.

Версия 0.2.6: публичное имя и визуальная айдентика изменены на Maydon. Новый знак, шапка, вход, LED-интерфейсы, иконки, название приложения и файлы новых размещений используют Maydon. На момент этого релиза технический URL оставался `https://adspace.fom-analytics.uz/`. Новые подтверждения используют версию условий `2026-09-23-v5`; ранее принятые снимки условий не изменяются.

Версия 0.2.5: личные и бизнес-сценарии на главной — фото, поздравление, признание, событие, бизнес. Основное действие ведёт к `/#ideas`, просмотр экранов — напрямую в каталог. Карточки передают `occasion` в URL, оформление и возврат после входа; неизвестные поводы игнорируются. Это подсказки для подготовки обычного материала, а не отдельные тарифы или обход двух проверок. В интерфейсе используются «размещение» и «заявка», роль `advertiser` сохранена на сервере, но показывается как «Автор размещения». Исторические согласования и исходные материалы не переписываются.


Версия 0.2.4: главная без каталога и фильтров; два действия «Разместить рекламу» и «Мои экраны»; локальный жирный кириллический шрифт Roboto Condensed (OFL); простой язык заказов вместо медиапланов/кампаний. Кабинеты: `/?view=orders` и `/?view=operator`, старые `?view=campaigns` сохранены. Вход `/login?role=advertiser` и `/login?role=operator` ведёт в кабинет фактической серверной роли; выбор карточки входа не меняет права существующего аккаунта. Выбор экранов и периода переживает вход в той же вкладке. Проверка навигации: `npm run test:navigation`. Источники стартовой базы: [исследование](docs/led-inventory-sources.md), [неопубликованные кандидаты](docs/led-inventory-candidates.json).


В версии 0.2.2 добавлен [ручной LED-пульт](docs/REMOTE-PLAYER.md): удалённая смена картинки/MP4 в отдельном техническом канале. Он сохранён, но не нужен в основном сценарии календарного показа. Интерфейс — красно-коралловая тема по референсу; зелёный оставлен только для статусов успешных действий.

Серверная версия — многопользовательский сервис с серверными правами доступа, а не песочница с переключением ролей. Старый ChatGPT Site остаётся архивным прототипом; его персональные D1-песочницы сюда не импортировались.

Актуальное описание: [сервер и ограничения](docs/SERVER-PILOT.md), [проверка с людьми](docs/PILOT-TESTS.md), [бизнес-модель](docs/BUSINESS-MODEL.md).

Работают каталог/карта/QR, спецификации экранов, календарь мест, 30-минутные резервы, кабинеты, загрузка и подготовка PNG/MP4, согласие владельца, сохранение версии условий, расписание и полноэкранный браузерный плеер, условные финансовые записи, споры и CSV. Демонстрационные карточки помечены; для реального теста оператор создаёт собственную карточку.

Реальных платежей, банковского эскроу, One ID, юридической электронной подписи, SMS и физического LED-контроллера нет. Журнал браузера не доказывает наружный показ. Email не верифицируется; автоматического восстановления пароля нет. Пилот — для небольшой приглашённой группы. Внешний backup и нагрузочная проверка нужны до расширения.

## Актуальный запуск

Node.js 22.13+ с `node:sqlite`; FFmpeg и FFprobe задаются переменными `FFMPEG_PATH`/`FFPROBE_PATH`.

```powershell
npm ci
npm run typecheck
npm run build
$env:APP_URL='http://localhost:3100'
$env:HOST='127.0.0.1'
$env:PORT='3100'
npm start
```

Первое обращение к `/api/workspace` создаёт схему. `node scripts/bootstrap-admin.mjs` создаёт первого администратора и приватный файл доступа только при отсутствии администратора. Не публикуйте `.local` или серверный каталог `data`.

`node scripts/test-server.mjs` запускает отдельный сервер и временную БД, проверяет права, календарь, модерации, условия, приватность, рендер PNG/MP4, плеер и условные возвраты. Локальный FFmpeg по умолчанию ищется в `.local/media/node_modules`; пути можно переопределить.

Актуальная логика — `lib/model.ts`, `lib/workflow.ts`, `lib/store.ts`, `lib/auth.ts`, `lib/assets.ts`. Публикация — `deploy/` (systemd, Cloudflare Tunnel, откат). Исторические ADR, исходные DOCX и D1-миграции сохранены. Активный сервер их не использует.

## Архив: описание Sites-прототипа 0.1 (не инструкция для текущего сервера)

Рабочий частный MVP для проверки сквозного размещения на LED-экранах. Версия 0.1.0-alpha.1. ADR: [docs/architecture/ADR-001.md](docs/architecture/ADR-001.md).

## Что можно сделать

Найти экраны по карте, району, цене, охвату и датам; собрать пакет; загрузить PNG/MP4; создать заявку; провести условную оплату; пройти две независимые проверки; подтвердить тестовый старт; получить историю и CSV. Оператор добавляет экраны, меняет тариф и закрывает периоды. Администратор меняет комиссию, приостанавливает оператора и разрешает спор с возвратом.

Каждый аккаунт имеет отдельную песочницу с переключением всех ролей. Доступа к чужим данным нет. Это не производственный многопользовательский RBAC. Поверхности и цены демо. Реальные платежи, CMS, SMS и фискализация не подключены.

## Быстрый сценарий

1. Войти и выбрать экран в каталоге. Для проверки файла скачать `test-creative.png` из формы заявки.
2. Указать даты и название, загрузить PNG, создать заявку.
3. В «Мои кампании» открыть её и выполнить тестовую оплату.
4. В «Модерация» одобрить контент. В «Для операторов» подтвердить техпроверку.
5. В операторском кабинете написать подтверждение и выполнить тестовый старт, затем завершение.
6. В «Мои кампании» скачать CSV. Для проверки спора открыть спор до завершения и разрешить его в «Финансы».

Отказ и доработка требуют причины. Новый креатив сбрасывает оба одобрения. Повторная оплата не создаёт новую запись. Пересекающиеся даты запрещены. Тариф заявки фиксируется при создании.

## Локальный запуск

Windows: двойной щелчок `START-ADSPACE-LOCAL.bat` запускает сайт и открывает браузер. `STOP-ADSPACE-LOCAL.bat` останавливает только процесс, созданный этим запускателем.


Нужен Node.js 22.13 или новее. Windows: команды выполняются в PowerShell; npm-скрипты запускают CLI через Node напрямую, чтобы знак `&` в пути не ломал Windows cmd shim.

```powershell
npm ci
npm run build
$env:WRANGLER_WRITE_LOGS='false'
$env:WRANGLER_LOG_PATH='.wrangler/logs'
node node_modules/wrangler/bin/wrangler.js d1 execute DB --config dist/server/wrangler.json --local --file drizzle/0000_zippy_grandmaster.sql --persist-to .wrangler/state
npm run dev
```

Миграция выполняется один раз на новую локальную базу. Вход локально: `http://localhost:3100/signin-with-chatgpt?return_to=/`. Локальную идентичность предоставляет официальный Sites dev plugin. Она не используется в опубликованной версии.

```powershell
npm run typecheck
npm test
npm run test:api
npm run build
```

API-проверка требует запущенный dev-сервер и мигрированную базу; создаёт тестовую завершённую кампанию. Данные dev-сервера живут в `.wrangler/state`, не в localStorage. Проверки не обращаются к платёжным системам и не вызывают CMS.

## Структура

- `app/`: интерфейс и HTTP-маршруты.
- `lib/domain.ts`: переходы состояний, стоимость, календарные ограничения.
- `lib/media.ts`: предварительная проверка контейнера файла.
- `db/` и `drizzle/`: D1 и миграции.
- `public/`: PWA, тестовый креатив.
- `docs/source/`: исходный DOCX, без изменений.
- `docs/architecture/`: ADR по структуре Marosim v0.9.

## До реального пилота

Нужны OTP, организации/RBAC, юридически подтверждённая схема расчётов, платёжные callbacks и сверка, реальные CMS и телеметрия, проверенные сведения об операторах, TTL резервов, нормализованные транзакционные таблицы, аудит зависимостей, полноценная проверка медиа и политика хранения. Сейчас нет реальных чеков, банковского эскроу или подтверждённых показов.
