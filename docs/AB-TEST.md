# Два варианта AdSpace UZ

Эксперимент оформления v1, версия приложения 0.1.0-alpha.4.

| Ссылка | Вариант |
| --- | --- |
| `/a` | Первоначальный зелёный каталог «Ваш бренд. На виду.» |
| `/b` | Текущий городской дизайн по референсу Blindspot с иллюстрацией Ташкента |
| `/test` | Распределение 50/50 с закреплением варианта на 30 дней в браузере |

Оба варианта опубликованы в одном Sites-проекте. Это позволяет использовать одинаковый API, каталог, тарифы, даты, авторизацию, хранилище и обработку заявок. Различаются заголовок, композиция, оформление и объясняющий блок. Вариант A восстанавливает оформление первого опубликованного MVP из Git `70c4960`; последующие функциональные исправления остаются общими.

Прямые ссылки `/a` и `/b` предназначены для просмотра и раздельных групп. Участникам случайного сравнения нужно выдавать только `/test`, чтобы выбор дизайна не зависел от исследователя. Повторный переход через `/test` сохраняет назначение. Очистка cookies, другой браузер или устройство создают новое назначение. Гарантируется равная вероятность, а не ровно половина пользователей в маленькой выборке.

Вариант сохраняется при переходах по кабинетам, при возвращении из регистрации, в ссылках QR и после обновления страницы. Общие пользовательские записи по-прежнему изолированы по аккаунту. Cookies назначения не содержат email или ID аккаунта.

Для ручного теста используйте одинаковое задание: подобрать экран и создать тестовую кампанию. Фиксируйте долю завершивших, время до заявки, ошибки и вопросы по цене/модерации. Не направляйте одного участника последовательно в A и B для измерения независимой конверсии: второй вариант получит преимущество знакомства с продуктом.

В этом изменении реализованы два варианта и распределение трафика. Автоматический сбор конверсий, статистическая значимость и панель результатов не добавлены. Победитель не определён; до начала количественного эксперимента следует зафиксировать метрику, требуемую выборку и способ сбора результатов.
